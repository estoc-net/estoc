# Conformance status

[Suite guide](README.md) · Phase 1

Where each required conformance case of the phase-1 suite stands in this repository: the code that implements it and the tests that exercise it. The specs own the cases; this page only reports on them, and is the one place where code and tests are tied to case IDs.

Assessed 2026-09-21 against `main` at `54f9b86` plus the changes made with this page; the host rows (SQ-28, SQ-34, SQ-39, VE-51, RZ-68) were reassessed the same day with the changes that built them. Every test cited was read, not only matched by title; the suites were not re-run case by case, so `verified` means "a test asserts this", and the continuous-integration run is what says the test passes. The Chromium half of the event-store storage cases is skipped when no browser is found.

| Status | Meaning |
|---|---|
| `verified` | Implemented, and at least one test exercises what the case says. |
| `partial` | Implemented; the Note names the clause no test exercises, or the part that is not built. |
| `untested` | Implemented; no test exercises it. |
| `missing` | Not implemented. |
| `n/a` | Binds no code here: the mediator, a documentation claim, or a feature the suite defers. |

## Baseline open items

In the 2026-09-21 baseline, no case was `missing` in the vault, the folds or the runtime. What is open falls into four groups.

**No exact move.** [SQ-39](vault-sqlite.md#sq-39): the hosts move a vault only as a portable snapshot, which takes fresh IDs, so the stopped-source clause binds nothing here. Two copies of one runtime folder that both went on being written are caught at their first merge, where the daemon renews its own identity and merges.

**The mediator.** [DD-42](distributed-delivery.md#dd-42) binds the mediator's forward handling, which lives in another repository.

**Readings to confirm.**

- [DD-61](distributed-delivery.md#dd-61): a reply with no eligible sender is not listed as pending work until a sender exists; from then on it is listed and sent by hand only. The case says "Missing sender leaves manual work".
- [VE-147](vault-events.md#ve-147): a `contact.channelsSet` without its `contact.created` yields a contact entry with a null origin that records list and `send` accepts. The case says the set "creates no missing contact".

**Test gaps.** Every other `partial` and `untested` row is implemented and names, in its Note, the clause no test exercises. Many are negative clauses that hold by construction (a fold that does not read the events in question) and would each take one contrasting scene to pin down.
